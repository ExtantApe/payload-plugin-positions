# Changelog

## Unreleased

- The repo, with the standard Payload plugin kit and an empty plugin. Nothing to install yet. Public since 2026-11-22.
- **Core.** The `position-grants` collection (holder, position, scope kind and id, start and end, granted by, status, revoke stamp, notes), host options for position types and scope kinds, `canGrant`, `canRevoke`, `canRead` and `refuseGrant`, audit hooks before and after grant, revoke and expiry, the `hasPosition` and `positionsOf` helpers, and `expireGrants` for a scheduled sweep. Without a `canGrant` that answers exactly `true`, nobody can grant. A unique `liveKey` makes the one-live-grant rule hold under concurrent requests.
- **Review fixes.** Resuming a paused grant, or moving an end date later or to none, now needs `canGrant` (given the existing grant and what is asked) and the veto; `canRevoke` is given `id` and `data`. Audit hooks for pause, resume and end-date change. The holder reaches `canGrant` as a plain id. Self-grants, self-resumes and self-extensions are refused unless `allowSelfGrant`. Grants can't be deleted, even with `overrideAccess`. Notes are readable only by people who pass `canGrant`; notes are capped at 2000 characters and scope ids at 200. Helpers only accept a user from the plugin's users collection. `refuseGrant` is required (`false` for none). New append-only `position-grant-history`.

- **Second review.** The veto sees the grant as it would be after an extension. Notes and history are read through a new `canReadPrivate` (nobody without it; history may be narrowed by a `where`). Every change is refused without database transactions unless `allowWithoutTransactions`, so a history failure always undoes the change. README says the unique index needs `ensureIndexes: true` on Mongo or a migration on SQL.
- **Third review (low items).** Who acted is recorded with its auth collection (`collection:id` in history, `{ collection, id }` in audit events); `grantedBy` and `revokedBy` stay empty for a user outside the users collection. A user who can't read a grant's notes can't overwrite them. Dates must be ISO strings; `'1'`, words, numbers and `0` are refused instead of read as a date or as no date.
- **Follow-ups.** The transactions check now happens at startup: the plugin begins a transaction and rolls it back, and refuses to start if the adapter returns none (db-mongodb with `transactionOptions: false` returns `null`, which the old check missed), unless `allowWithoutTransactions`. The per-request check stays. `canReadPrivate` gets `grant: undefined` instead of a blank grant when there is no document (the type now says so). Dates must be real (`2026-02-30` is refused) and a time must carry a zone. A `where` on notes is refused, since which rows match would tell the asker what the notes say. The duplicate-grant lookup no longer asks for a page count: Payload's Mongo adapter sent the find and its count together as the first queries of the transaction, and they now and then raced to start it (NoSuchTransaction, about 1 in 7 requests on a fresh session). The veto always sees `endsAt` as `null` when there is no end. README notes that an object from `canRead`, or from `canReadPrivate` for the history, is a `where` and `{}` matches every row, and that the startup check can be skipped (`disableOnInit`, or a second `getPayload` after a failed start) so the per-request check is what stands behind it.

Tested: 64 tests against a real Payload and an in-memory MongoDB. They cover grant and refusal paths, scope and date validation, duplicates (six simultaneous grants, one wins), a host veto (also for server code, resume and extension), fail-closed access with six wrong kinds of answer, a revoke-only user who can't resume or extend, self-grants both ways, no deletes, notes hidden from holders and length limits, the history, date windows, revoke, pause, final states, expiry and audit order, and refusals through bulk update, REST and GraphQL. Also a veto that refuses a long extension, notes and history narrowed by scope, none without `canReadPrivate`, a failing history write undoing a grant and a pause, and refusal without transactions. Follow-ups: the startup check against a mock shaped like the adapter (`beginTransaction` returns null, undefined or throws, or an id that gets rolled back) and a real adapter with transactions off, the per-request check with start-up skipped, a `where` on notes refused, no grant passed to `canReadPrivate` for the history, impossible dates and zoneless times, the veto seeing a null end date, and notes and history hidden over REST and GraphQL with no `canReadPrivate`. Mutation checks (no resume and extend gate, no delete hook, loose `canGrant`) each fail tests.
Not tested: a standalone Mongo that passes the startup probe; a real app or the admin in a browser; a very large number of grants.
